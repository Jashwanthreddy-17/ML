# Player Performance Prediction Using Ridge and Lasso Regression

Predicts how many runs a batter will score in an innings, from IPL ball-by-ball data.
**Backend:** Python (Flask + scikit-learn) · **Frontend:** HTML/CSS/JS

## Project structure

```
player-performance-prediction/
├── backend/
│   ├── train.py          # feature engineering + trains Ridge/Lasso/baseline
│   ├── visualize.py      # generates report charts -> frontend/figures/
│   ├── app.py            # Flask API + serves the frontend
│   ├── requirements.txt
│   └── artifacts/        # generated by train.py (models, metrics, players)
├── frontend/
│   ├── index.html        # Predict / Model Comparison / Graphs / About pages
│   ├── styles.css
│   ├── app.js
│   └── figures/          # PNG charts (generated by visualize.py)
├── data/
│   └── match_data.csv    # ball-by-ball deliveries (16 IPL seasons)
└── README.md
```

## Quick start

**Linux / macOS:**

```bash
cd backend
pip install -r requirements.txt
python train.py      # ~1-2 min: builds features, trains, writes artifacts/
python visualize.py  # generates charts -> ../frontend/figures/
python app.py        # open http://localhost:5000
```

**Windows (Command Prompt):**

```bat
cd player-performance-prediction\backend
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
.venv\Scripts\python train.py
.venv\Scripts\python visualize.py
.venv\Scripts\python app.py
```

Then open http://localhost:5000 in your browser.
(Requires Python 3.10+ from python.org. `~` and `.venv/bin/` are Linux paths — on Windows use the commands above.)

|--------|---------------|-------------|
| GET    | `/api/meta`   | teams, venues, test metrics, split info |

| POST   | `/api/predict`| `{player, opponent, venue, innings}` → `{predictions: {ridge, lasso}, player_stats, context}` |

## Methodology (matches the project abstract)

1. **Target:** `innings_runs` = sum of `runs_off_bat` per batter per match innings.
   Extras are not credited to the batter; valid zero scores are retained.
2. **No leakage:** every feature is computed from the player's innings *strictly
   before* the current match date. The current innings' runs, balls, fours and
   sixes are never inputs.
3. **Features:** career average/strike-rate/totals, last-5 and last-3 form,
   consistency (std of last 5), career best, days since last match, plus
   pre-innings context (innings number, venue, batting/bowling team).
4. **Models:** RidgeCV (L2 shrinkage) and LassoCV (L1 shrinkage + feature
   selection) vs a mean baseline, with features standardised.
5. **Validation:** chronological split — train on matches before 2022,
   test on 2022–2023. Compared with MAE, MSE, RMSE and R².

Predictions are statistical estimates for demonstration only.

## Deploy (Render, free)

Netlify can't host the Python backend (static files only, no Python runtime),
so the app deploys as one service on Render, which runs it exactly like
`python app.py` does locally.

1. **Upload the dataset** to the repo via the GitHub website: open
   `player-performance-prediction/` → Add file → Upload files → drop in
   `match_data.csv` inside a `data/` folder. (36 MB — too large to push via API;
   the file must be at `player-performance-prediction/data/match_data.csv`.)
2. Go to [render.com](https://render.com), sign up with GitHub (free).
3. New → Blueprint → select your `ML` repo. Render reads `render.yaml` and
   creates the `player-performance-predictor` web service.
4. The build installs dependencies, runs `train.py` and `visualize.py`, then
   starts the app with gunicorn. Open the URL Render gives you.

Note: the free tier sleeps when idle, so the first visit after a while takes
~30–60 s to wake up.
